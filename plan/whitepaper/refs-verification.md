# refs.bib verification log

Built 2026-11-01 for the HASHIRU v2 whitepaper. Each entry in `refs.bib` was fetched from, or checked field by field against, a source queried on that date. No entry was written from memory.

## Method

- **Venue records.** ACL Anthology `.bib` files, PMLR abstract pages (embedded BibTeX), NeurIPS proceedings pages and BibTeX, OpenReview (`/notes/search` API: the venue note's `_bibtex`, author list, and `venueid`), and CrossRef DOI content negotiation (`Accept: application/x-bibtex`). CrossRef bibliographic search was used to find DOIs and to look for journal or proceedings versions of every preprint.
- **Preprints.** arXiv export API (title, authors in order, first-submission date, primary category, comments, journal-ref, DOI).
- **Secondary cross-checks.** Semantic Scholar Graph API (single and batch lookups by arXiv ID), and DBLP records mirrored on OpenReview (`venueid = dblp.org/...`, or `DBLP:` keys inside `_bibtex`).
- **Specs and software.** Official spec sites (version banner or "current version" text), the GitHub REST API (repository, organisation display name, latest release tag and date), and LICENSE files (copyright holder).
- **Automated re-checks.**
  - All 17 arXiv `@misc` entries were compared against the arXiv API: title, author family names in order, full names, and year. The only mismatch is Magentic-One (see notes).
  - The 8 OpenReview-sourced entries were re-fetched and compared on title and full author list. All match.
  - The ACL, PMLR, NeurIPS and CrossRef entries were compared on title, authors, pages, volume and year. All match.
  - The file compiles cleanly with `pdflatex` + `bibtex` (`plainnat`, `\nocite{*}`): 46 entries, 0 warnings.
- **Access limits.** `dblp.org` (and its `uni-trier`/`dagstuhl` mirrors) and `ojs.aaai.org` sit behind an Anubis proof-of-work bot wall that blocks scripted clients. I did not try to get around it. DBLP data therefore came from DBLP records mirrored on OpenReview, and AAAI data from CrossRef (DOI `10.1609/aaai.v40i35.40226`). The Semantic Scholar per-paper endpoint is heavily rate-limited, so the batch endpoint was used for most IDs.
- **Key convention.** `lastnameYEARfirstword`, lowercased, with punctuation and hyphens removed, and leading articles ("A", "An", "The") skipped. Examples: `kim2024llm`, `coase1937nature`. When the venue title differs from the arXiv title, the key follows the venue title (`narayan2025costefficient`). For organisation-authored specs and software, the organisation name stands in for the last name (`berriai2026litellm`, `modelcontextprotocol2026specification`).
